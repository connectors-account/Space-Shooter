### Starfall Squadron — Windows desktop Unity source

A compact, single-player 2D arcade space shooter. This is a **native Windows desktop project**, not a website. All game code, PNG sprites, PCM WAV sounds, project settings, and the scene/prefab generator are included. No asset-store purchases, accounts inside the game, remote assets, Python execution, or package downloads beyond Unity's own built-in modules are needed to play/build it in Unity.

**Validation boundary:** Unity is not installed in the delivery environment. The full Unity project has **not** been compiled, imported, or playtested here, and no Windows executable is supplied. Static syntax/project/asset checks and compiled engine-independent rules tests passed; see `Docs/Validation.md`. The first Unity import is an explicitly unverified integration step.

### Exact editor assumptions

- **Unity Editor 6000.0.62f1**, Unity **6.0 LTS**, revision `f99f05b3e950`.
- Official release/download page: https://unity.com/releases/editor/whats-new/6000.0.62f1
- Windows 10/11 x64; Unity Hub with a valid Unity license (Personal when eligible).
- Built-in Render Pipeline, orthographic SpriteRenderer visuals; no URP/HDRP or 2D lighting package.
- Built-in **Input Manager** (`Active Input Handling: Input Manager (Old)`, not new Input System only).
- **Mono** scripting backend, Windows **x86_64**. Uses Unity's default managed API compatibility setting; no unsafe code or platform-specific plugins.
- Only three manifest dependencies: `com.unity.modules.audio`, `com.unity.modules.imgui`, `com.unity.modules.jsonserialize`, each pinned to **1.0.0**. These ship with the Editor; no external runtime packages, TMP, or Input System package.
- UI uses Unity's built-in IMGUI/font. Remaining default project settings and package lock file are generated by the pinned Editor on import. The Editor setup script explicitly applies window/build/input settings.
- This is a reproducible version pin, not a claim that this patch is the latest Unity release.

### Open and play — on your Windows machine

1. Install Unity Hub. From the release page above choose **Install with Unity Hub** for **6000.0.62f1**. Install the Windows Editor. Its standard Windows Mono player support is required. If Hub offers a Windows Build Support module, include it; **IL2CPP support and Visual Studio are not required** for this Mono build.
2. Extract the complete ZIP into a writable local folder, for example `C:\UnityProjects\space-shooter-desktop`. Do not open the project from inside the ZIP.
3. Hub → **Projects → Add → Add project from disk**. Select the folder containing `Assets`, `Packages`, and `ProjectSettings`. Open it with **6000.0.62f1**. Do not create a new URP template or copy only the scripts.
4. Wait for asset import and script compilation. The `[InitializeOnLoad]` bootstrap automatically configures sprites and gamepad axes and generates:
   - `Assets/Starfall/Generated/Starfall.unity`
   - `Assets/Starfall/Generated/GameAssets.asset`
   - Nine serialized prefabs in `Assets/Starfall/Generated/Prefabs` (player, four enemies, projectile, three pickups).
   - The scene's camera, audio listener, controller, HUD, and asset references; it also registers the scene in Build Settings.
5. Choose **Starfall → Open Game Scene**. This works even if the initial scene was not automatically opened. Press Unity's **Play** button, focus the Game view, then click **Launch** or press **Enter**.
6. If generation is interrupted, resolve any Console error and choose **Starfall → Rebuild Generated Content**. This intentionally overwrites only the generated game scene, prefabs, and asset configuration, and asks before doing so. Exit Play mode first. It does not rewrite the handwritten game scripts or bundled art/audio.

Generated scene/prefab YAML is deliberately **not** hand-authored in this source delivery. Unity creates it using its supported serialization APIs. All asset references are assigned by the generator; Unity creates `.meta` GUIDs on import, so there are no external or pre-existing GUID dependencies. Keep generated content and `.meta` files when committing your imported project.

### Build an executable — on your Windows machine

1. Exit Play mode.
2. Choose **Starfall → Build Windows x64**. The build menu uses the generated scene, Windows x86_64, Mono, and a non-development build.
3. When Unity reports success, run `Builds\Windows\Starfall.exe` inside your project.
4. **Distribute the entire `Builds\Windows` folder**, not just the EXE. It includes the data directory, UnityPlayer DLL, Mono runtime files, and any other files Unity produces.

Manual alternative: **File → Build Profiles → Windows**, switch to that platform, select **Intel 64-bit / x86_64**, ensure `Starfall.unity` is enabled in Scene List, choose **Mono** in Player Settings → Other Settings → Configuration, then Build to a new folder. The exact panel labels may vary slightly within Unity 6.

Optional batch build in Windows PowerShell (close the interactive Editor first, adjust the project path):

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.0.62f1\Editor\Unity.exe' `
  -batchmode -quit `
  -projectPath 'C:\UnityProjects\space-shooter-desktop' `
  -buildTarget Win64 `
  -executeMethod Starfall.Editor.ProjectSetup.BuildWindows `
  -logFile 'C:\UnityProjects\space-shooter-desktop\build.log'
```

If Unity says Windows support is missing, use Hub → Installs → the editor's settings → Add modules, or reinstall that editor with its Windows player support. If the Console reports that the old Input API is disabled, set **Edit → Project Settings → Player → Other Settings → Active Input Handling → Input Manager (Old)** and accept the Editor restart. The delivered setting already selects this.

### Controls

| Action | Keyboard / mouse | Typical Xbox-compatible gamepad |
|---|---|---|
| Move | WASD or arrow keys | Left stick |
| Fire (hold) | Space or left mouse button | A / button 0 |
| Launch / replay / resume | Enter or UI button | A / button 0 |
| Pause / resume | Escape or P | Start / button 7 |
| Restart run | R | Y / button 3 |
| Main menu while paused / at results | Backspace or UI button | B / button 1 |
| Mute / unmute | M or UI button | X / button 2 |
| Quit | Title screen Quit or Alt+F4 | Use window close / mouse |

Gamepad buttons use the legacy Windows joystick indices; mappings differ on non-XInput controllers. Keyboard and mouse are the primary desktop controls. Mouse aims nowhere: the ship shoots forward. Menu actions have direct gamepad bindings, not a gamepad cursor. Touch is intentionally out of scope for this Windows desktop game.

### Rules and content

- Move freely inside the fixed playfield. Diagonal movement is normalized; the camera never rotates or follows the ship. Resizing preserves a 16:9 playfield with letterboxing.
- Hold fire to shoot. Player shots cannot hit the player; enemy shots cannot hit enemies. Moving segment/circle tests resolve projectiles without tunneling; smaller player hit circles make near misses forgiving. No Unity Rigidbody/Collider dependency is used.
- Five hull points; damage grants a short invulnerability window. **Escaped enemies cost one hull point, ignoring shields/invulnerability.** This discourages hiding at the edge.
- Four waves spawn 8, 11, 14, and 17 ships, followed by a dreadnought boss. Scouts fire straight, fighters aim at the player, gunships fire three-shot fans, and the boss alternates aimed fans and rotating radial bursts.
- Waves have safe short introductions/intermissions. Final boss destroyed and field cleared → sector-clear screen. Hull reaches zero → game-over screen. Restart always clears shots, enemies, pickups, effects, buffs, health, score, and wave state.
- Every fourth non-boss kill drops a rotating supply type: repair (+2, capped at 5), triple shot (12 seconds), shield (8 seconds). Additional pickups refresh that buff's duration. Collecting any capsule adds 25 points.
- Scores: scout 100, fighter 175, gunship 250, boss 2,000. Best score and audio preference persist locally via PlayerPrefs. On Windows the usual store is `HKCU\Software\Starfall Studio\Starfall Squadron`.
- Three parallax star layers, impact/explosion particle bursts, invulnerability blink, ship banking, pickup rotation, boss health bar, wave banners, and score/health/buff HUD.
- Nine sound effects plus a looped ambient drone are bundled. No copyrighted music or external audio downloads. Pause freezes gameplay; the quiet ambient layer continues. Losing application focus pauses the run.

### Source map

| File | Responsibility |
|---|---|
| `Assets/Starfall/Scripts/FlightGame.cs` | Compact game state machine, movement, waves, patterns, collisions, powerups, scoring, audio, pools |
| `Assets/Starfall/Scripts/FlightHud.cs` | Scalable title/HUD/pause/results UI and buttons |
| `Assets/Starfall/Scripts/PilotInput.cs` | Keyboard, mouse, gamepad input |
| `Assets/Starfall/Scripts/SpaceBackdrop.cs` | Three-layer starfield |
| `Assets/Starfall/Scripts/GameRules.cs` | Engine-independent numeric rules and swept collision geometry |
| `Assets/Starfall/Scripts/GameAssets.cs` | Typed serialized asset references |
| `Assets/Starfall/Editor/ProjectSetup.cs` | Idempotent import bootstrap, prefabs/scene, Windows build menu |
| `Assets/Starfall/Art`, `Audio` | Actual bundled PNG/WAV assets |
| `Tools` | Optional asset preparation and source/rules checks; never required by Unity |
| `Docs` | Validation evidence, Windows smoke checklist, asset contact sheet |

The controller keeps simulation in one readable place rather than spreading a small game across hundreds of components. Bullet/spark renderers are pooled; entity counts are bounded. This is a simple arcade source project, not an ECS framework or a performance benchmark.

### Optional local source checks

These do **not** test Unity APIs, Editor serialization, rendering, or Windows behavior:

```sh
python -m pip install Pillow tree-sitter tree-sitter-c-sharp
python Tools/check_project.py
mcs -out:RulesTests.exe Assets/Starfall/Scripts/GameRules.cs Tools/RulesTests.cs
mono RulesTests.exe
```

`Tools/prepare_assets.py` can regenerate the bundled sprite crops and synthesized sounds from the included atlas; it requires Pillow. You do not need it for import or play. See `ASSETS.md` for provenance and `LICENSE` for the source license.
