# Space Shooter

Minimal **Windows desktop Unity/C# game**. One runtime script creates the camera, coloured rectangular ships, shots and UI. No prefabs, tags, Inspector references, external art, audio or third-party packages are required. This is source, not a compiled `.exe`.

### Open and play — on your Windows computer

1. Download the complete `space_shooter` folder. In Unity Hub, install **Unity 6.3 LTS (6000.3.x)**, preferably its latest available patch. The project version file records the initial 6000.3.0f1 release; Hub can open/upgrade it with your installed 6.3 LTS patch.
2. In Hub, use **Add > Add project from disk** and select `space_shooter` (the folder containing `Assets`, `Packages` and `ProjectSettings`). Open it and let Unity import it. Missing optional/default project settings are generated by Unity.
3. Open `Assets/Scenes/Main.unity`, press **Play**, and click the Game view to give it keyboard focus. The scene intentionally has no camera or game objects wired to scripts: startup code creates the game when Play starts.

**Controls:** WASD or arrow keys move; hold Space to shoot. Destroying an enemy earns **10 points**. One enemy touching your ship **or reaching the red bottom line** ends the game. Click **Restart**, or press **R / Enter**, to reset. Losing focus freezes gameplay until you return. Close the desktop window to quit.

If you copy the script into a different project instead of opening this one, use the **Built-In Render Pipeline**, and set **Edit > Project Settings > Player > Other Settings > Configuration > Active Input Handling** to **Input Manager (Old)** or **Both**. This delivered project already selects the old input system and does not need input axes configured. Use normal Unity Play Mode reload settings.

### Build a Windows executable — on your Windows computer

1. Open **File > Build Profiles**. Select the **Windows** platform/profile; if needed, use **Add Build Profile**, select Windows, and activate it with **Switch Profile**. If Unity asks for platform support, install the matching Windows support through Hub.
2. Choose **Intel 64-bit / x86_64** architecture. Use **Mono** scripting backend in **Player Settings > Other Settings > Configuration** for the simplest build (the project requests Mono). Leave **Create Visual Studio Solution** and **Development Build** off. An IL2CPP build additionally needs its Windows support module and Microsoft C++ build tools; it is unnecessary here.
3. Check the **Scene List**: `Assets/Scenes/Main.unity` must be enabled and first. The supplied global build settings already include it. If your profile overrides the list, add Main with **Add Open Scenes** (or drag it from the Project window); use **Add Settings > Scene List** if the profile does not show that section.
4. Click **Build**, create/select `Builds/Windows` inside this project, and name the executable `SpaceShooter.exe` if prompted. Run the generated executable on Windows.
5. To share the game, distribute the **entire generated Windows build folder**, not just the `.exe`. Keep its `_Data` directory, `UnityPlayer.dll` and any other generated runtime files alongside it.

### Source and implementation

- `Assets/Scripts/SpaceShooter.cs` — complete game implementation, including runtime setup, movement, spawning, swept rectangular collision checks, scoring, game over, restart and UI.
- `Assets/Scenes/Main.unity` — minimal startup scene, included in build settings.
- `Packages/manifest.json` — only Unity's built-in IMGUI and legacy input modules.
- `ProjectSettings/` — Unity version, default window/input settings and enabled scene.

The fixed playfield is 16 × 12 units. Movement is normalized diagonally and time-scaled; the timestep is capped after stalls. The camera keeps the playfield visible on resize. Collision boxes approximate each ship's full silhouette; swept relative-motion checks prevent shots from skipping enemies. Shots resolve before ship collisions. Restart clears existing enemies and shots without reloading the scene. There is one enemy type and no win condition: survive and increase your score.

### Verification and limits

Source-only delivery. Checks on the Linux authoring machine cover C# syntax parsing, JSON/YAML parsing, matching scene GUIDs/build configuration, required gameplay code paths and Git whitespace checks. These are **not Unity compilation or runtime tests**. No Unity editor or Windows build was run, no executable is included, and a Windows executable cannot be run on this Linux machine. Unity import, shader/module inclusion, gameplay feel and the final Windows build still require verification in Unity on your Windows computer. No stub compilation is used or claimed.
